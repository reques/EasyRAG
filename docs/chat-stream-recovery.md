# 对话任务的权限、重连与取消

MCP 管理接口 `/api/v1/mcp/*` 和全局旧接口 `/api/v1/chat`、`/api/v1/ingest`、`/api/v1/tools`、`/api/v1/kb/*` 需要有效的管理员登录。管理员指数据库中的 `role=admin` 或 `is_superuser=true`，被停用的账号不可访问。普通用户继续使用带用户归属校验的 `/api/v1/chat/*`、`/api/v1/knowledge/*` 等接口。`/api/v1/health` 保持公开，供健康检查使用。

## 连接与任务分开

`POST /api/v1/chat/stream` 接受可选 UUID `request_id`。客户端首次提交时生成一次，网络重试复用相同 ID 和请求内容。相同 ID 返回同一个任务；将该 ID 用于另一份请求会返回 409。数据库也限制每个会话同时只能有一个活动任务，避免并发请求生成重复对话。同步的 `/api/v1/chat/send` 使用同一套执行和保存逻辑。

响应头包含 `X-Chat-Stream-Id` 和 `X-Conversation-Id`。每条 SSE 事件包含 `stream_id`、递增的 `sequence`，并带 SSE `id`。最终回答和 `done` 事件在同一个数据库事务里提交，保存失败不会发送成功事件。

浏览器断网、关闭标签页或切换会话，只会断开订阅。后台执行继续，提问、进度和最终回答保留。前端自动重新连接，并按序号补读、过滤重复事件。刷新页面后，通过会话的最新任务重新订阅。

| 接口 | 用途 |
| --- | --- |
| `GET /api/v1/chat/streams/{stream_id}/events?after=N` | 补读序号大于 N 的事件，继续等待执行完成 |
| `GET /api/v1/chat/conversations/{conversation_id}/stream` | 获取当前会话最新任务及其状态 |
| `POST /api/v1/chat/streams/{stream_id}/cancel` | 主动请求取消，重复调用安全 |
| `POST /api/v1/chat/conversations/{conversation_id}/resume` | 服务进程中断后，复用原提问从 checkpoint 恢复 |

所有接口都验证当前用户及任务/会话归属；其他用户访问返回 404。补读请求使用登录头认证，URL 不携带令牌。`after` 不能为负或超过任务当前序号。

## 主动取消

“停止生成”发送取消请求，状态先变为 `cancel_requested`。取消信号传播到模型、工具和子任务的请求上下文，阻止继续调度；执行线程收尾后，记录 `cancelled`，不保存成功回答。提问和已记录的执行事件保留。即使取消与回答保存同时发生，也只会有一个终态；已经提交成功的回答不会被事后的取消删除。

断网时取消请求可能尚未送达，界面会明确提示并重试，不会把断网显示成“已停止”。已主动取消的任务不能当作断点恢复；发送新消息即可开始下一轮。

模型 HTTP 请求支持直接取消：同步 OpenAI/LangChain 调用通过进程内专用异步 I/O 循环读取网络，异步调用也监听同一个任务取消信号。等待响应头、等待首个正文 token、仅输出推理内容和正文流暂停时均可中断读取并关闭该次连接，无需等待原来的读取超时。共享客户端中的其他任务不受影响，取消也不会触发 SDK 重试或兜底生成。

第三方工具已经执行的写操作无法回滚；尚不支持中断的工具 I/O 仍需等待其返回或超时。取消确认不代表撤销已经发生的外部操作。浏览器断网仅断开订阅，不会触发模型取消。

## 服务重启与部署

启动时 `init_db()` 自动创建 `chat_streams` 和 `chat_stream_events` 两张表及索引，无需修改现有表。更新代码后需重启 API 服务。

执行进程每 5 秒更新心跳。异常退出后，超过 90 秒未更新的任务在查询/重连时被标为 `interrupted`，保留提问和事件，允许用户明确点击“从断点恢复”。正常关闭也会请求执行线程停止并记录中断。

这次实现继续使用现有 API 执行器，没有引入分布式任务队列。单纯浏览器断网支持自动重连；API 进程丢失后需要显式恢复，checkpoint 的可恢复范围取决于现有配置和持久化存储。恢复第三方写操作仍需工具自身保证幂等。
