# Skill 配置管理设计

## 目标

在对话输入框中显式选择本次请求使用的 Skill，并提供用户级配置入口。Skill 不是纯前端标签，而是由“工作指令 + 工具白名单”组成的可执行配置包。

## 方案

- 内置 Skill 由代码维护，首批提供知识库研究、联网研究、数据分析、专业写作和法律分析。
- 自定义 Skill 按用户保存到 PostgreSQL，可创建、编辑和删除。
- 前端只保存、提交公开 `skill_id`，不保存执行指令的副本。
- 每次请求最多选择 3 个 Skill；后端重新解析归属并合并指令和工具权限。
- 未选择 Skill 时保持现有 Agent 行为；选择后仅允许所选 Skill 声明的工具集合。
- Skill 指令注入意图识别、ReAct、单 Agent 回答和多 Agent Worker，确保同步与 SSE 路径一致。

## 接口

- `GET /api/v1/chat/skills`：返回内置/自定义 Skill 及当前可配置工具。
- `POST /api/v1/chat/skills`：创建自定义 Skill。
- `PUT /api/v1/chat/skills/{skill_id}`：更新当前用户的自定义 Skill。
- `DELETE /api/v1/chat/skills/{skill_id}`：删除当前用户的自定义 Skill。
- `/chat/send` 与 `/chat/stream` 请求增加 `skill_ids`。

## 前端交互

- 输入框左下区域增加 Skill 选择按钮。
- 已选 Skill 以可移除胶囊显示在输入框内，发送前一目了然。
- 下拉面板支持搜索、多选和进入配置管理。
- 配置弹窗展示内置 Skill，并支持填写名称、说明、工作指令及勾选工具。
- 浏览器记住最近选择，但服务端始终以本次请求传入并通过权限校验的 ID 为准。

## 安全与限制

- 自定义 Skill 只能引用注册表内的工具名。
- 工具调用阶段再次检查请求级白名单，防止模型伪造工具名。
- 自定义 Skill 按 `owner_id` 隔离；内置 Skill 不允许修改或删除。
- 名称、说明、指令、工具数量和单次选择数量均有限制。

## 验证

- 单元测试覆盖内置目录、用户隔离解析、工具白名单和请求模型。
- 后端完整测试、Python 编译检查、前端生产构建。
- 浏览器验证选择、创建、编辑、删除和发送请求携带 Skill 的完整流程。
