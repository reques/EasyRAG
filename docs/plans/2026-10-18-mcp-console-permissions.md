# MCP 页面权限修复

## 复现与原因

普通账号访问 `/api/v1/mcp/servers` 返回 403 `Administrator required`，与用户截图一致。该接口返回全局 MCP 连接配置，包括 Headers、环境变量和凭据，必须保留管理员限制。前端未感知权限，直接请求完整配置并显示管理入口，导致普通账号进入 MCP 页总是报“配置加载失败”。已确认截图中的 feifei 是正常启用的普通账号，不自动修改其角色。

## 修复

- 新增需要登录的 `GET /api/v1/mcp/overview`，显式白名单序列化服务名称、状态、传输类型、已放行工具与计数所需字段。省略 URL、命令、目录、环境变量、Headers、令牌、配置描述与原始错误。错误仅显示通用提示。
- `can_manage` 来自后端当前用户信息。前端普通账号只请求概览，展示只读说明，不请求管理员配置和工具 schema 接口，也不显示添加、广场安装、启停、编辑和删除入口。
- 管理员通过概览确认权限后继续请求原完整配置接口。原有全部 MCP 管理及旧接口均保留管理员校验，角色在两次查询之间被撤销时回退到脱敏概览。
- 同时统一空工具白名单行为：显式 `[]` 表示禁止全部，不能被运行时或广场安装转换为全量允许；`None` / 省略继续采用原默认 `['*']`。

## 验证

后端回归包括匿名拒绝、普通账号只读、管理员管理、凭据标记不出现在概览、工具白名单过滤，以及全部既有管理 API 的 401 / 403 边界。前端测试覆盖普通账号零管理员请求、管理员完整加载、撤权回退和网络错误。最终更新本地前后端，以普通账号在浏览器验收真实服务列表与工具展开。
