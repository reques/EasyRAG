# Ollama NaN 自动 CPU 重试

目标：修复 `servicing_details.docx` 的第 10 个文本块导致批量嵌入失败的问题。
已实测默认推理返回 `json: unsupported value: NaN`，同一文本使用 CPU 可生成有限的 1024 维向量。

实现：

1. 在 Ollama 嵌入请求边界识别服务端非有限数错误，以及成功响应中的 NaN/Inf。
2. 当前失败批次以 `options.num_gpu=0` 重试一次，保持输入、输出顺序。
3. CPU 请求设置 `keep_alive=0`；不修改全局模型配置。
4. 写入向量库前验证向量数量、形状、数值类型及有限性。
5. CPU 仍失败则明确报告，避免无界重试。普通网络、认证及服务错误维持失败行为。
6. 日志仅记录模型名、批次数量与重试结果，不包含文档文本。

验证与部署：先覆盖普通请求、500 NaN、200 NaN/Inf、CPU 失败、普通 HTTP 错误及跨批次顺序；
再构建、重启后端，通过既有重新索引流程处理原文件，检查 PostgreSQL 状态和 Milvus 中的实际向量。
保留原文件与文档 ID。根目录测试继续仅在本地使用。

## 验收结果

- 56 项相关回归测试通过。法律规则抽取用例隔离真实 LLM，消除外部输出导致的波动。
- 后端镜像已构建并重启，前后端健康检查正常。
- 原文件重新索引真实触发 `non-finite inference result`，11 个输入的 CPU 重试成功。
- 同一文件 ID 最终状态为 `completed`，进度 100%，错误信息已清空。
- Milvus 中存在该文件的 11 个向量，全部为有限的 1024 维数值；实际相似度搜索成功。
- CPU 重试后，后续默认嵌入请求仍可加载 GPU 模型。
