# 空白草稿与项目菜单修正

## 用户要求与设计

“新建会话”进入唯一的临时空白草稿，不立即写数据库。同一工作区重复点击复用草稿，保留尚未发送的输入；切到已有会话后丢弃草稿。首次消息送达服务端时，使用现有 stream admission 事务一起创建会话、用户消息与执行记录，获得正式 Session ID。仅修改标题不算有聊天内容，已有空记录从侧栏过滤，不自动删除数据。

项目菜单新增置顶 / 取消置顶、编辑、分区、在资源管理器中打开、归档聊天、移除项目。分区用于组织项目，可创建和移除自定义分区；项目移除仍保留聊天。聊天归档持久化并可从归档列表恢复，归档不删除消息或 checkpoint；运行中任务先阻止批量归档，避免在侧栏静默隐藏任务。

资源管理器属于浏览器宿主机功能，不能用 Docker 内目录冒充。用户已选择关联本机目录并提供仅本机可用的服务。实现为 `scripts/workspace_opener.py`，仅监听回环地址，检查网页来源和当前用户的项目归属，拒绝客户端直接传目录或命令。

## 实施与验证

1. 前端 store 回归用例先复现重复点击产生多条空记录、切换后遗留记录的问题。
2. store 改用不持久化草稿，ChatView 首次发送传入工作区；stream fingerprint 仅在非空时加入新字段，兼容已有幂等记录。
3. Workspace 增加置顶、目录和分区字段；Conversation 增加归档时间。迁移幂等，保留全部现有 ID 和消息。
4. 所有新 API 按用户校验所有权；分区归属、归档与恢复均覆盖跨用户拒绝用例，批量操作与 stream admission 共用锁顺序。
5. 前端补齐项目菜单、编辑 / 分区弹窗、归档列表与恢复入口；空草稿不显示复制 Session ID 或服务端操作。
6. 隔离 PostgreSQL 测试首次发送原子持久化、空记录标记、归档恢复、权限与并发；前端测重复新建、草稿丢弃、输入保留、迟到握手和项目分区；最终构建、更新本地服务、浏览器实测。
