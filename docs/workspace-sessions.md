# 工作区与会话

左侧“项目 / 工作区”旁的文件夹加号用于创建工作区。创建后会打开第一个会话；工作区右侧的加号可以继续创建会话。顶部“新建会话”固定在“最近”中创建，即使当前打开的是项目内的会话。项目右侧的加号仍在对应项目中新建。

“新建会话”进入临时草稿，尚未发送时不会写入数据库。同一草稿中重复点击保持原样（包括未发送的输入）；切到已有会话后草稿自动消失。首次发送消息时，后端在同一事务内保存会话、用户消息和执行记录，并生成正式 Session ID。失败发生在事务之前时不会残留空会话。

顶部 Session 按钮或会话菜单可以复制正式 ID，地址栏中的 `?session=<UUID>` 可以定位到同一会话。草稿没有可分享的 Session 链接。链接仍然需要登录，只有会话所有者可以访问。此前版本产生的空记录会从侧栏隐藏，原数据库记录保留。

每个工作区标题右侧常驻“⋯”按钮，点击展开项目菜单；旁边的“＋”用于新建会话。项目菜单支持置顶、编辑项目名称与本机目录、移动到自定义分区、在资源管理器中打开、归档聊天和移除项目。置顶项目优先显示，取消置顶后回到所属分区；分区可以重命名和移除，移除分区保留项目。

会话可以重命名、移动、归档、删除和生成摘要标题。默认展示每组近期五条会话，点击“展开全部”查看其余记录，也可以搜索名称或完整 Session ID。窄屏点击顶部侧栏按钮打开工作区列表。

## 归档与恢复

项目菜单“归档聊天”会归档该项目下所有已有消息的聊天，项目本身继续保留。正在运行的任务需要先停止，避免被静默隐藏。归档后记录从侧栏消失，可从底部“已归档聊天”恢复并打开；恢复继续使用原 Session ID、消息、任务和 trace。直接打开归档会话链接时可以阅读历史，恢复后才能发送新消息。

## 在资源管理器中打开

在项目菜单“编辑”中填入本机已存在的目录，例如 `E:\LearnAgent\EasyRAG`，保存后点击“在资源管理器中打开”。关联目录仅用于打开资源管理器，不自动上传文件，也不向 Agent 授予目录访问权限。

Docker 后端不能直接打开浏览器宿主机的资源管理器，因此提供宿主机辅助服务。Windows 上启动：

```powershell
.\scripts\start-workspace-opener.ps1
```

服务只监听 `127.0.0.1:18765`，默认允许来自 `http://localhost:5173` 和 `http://127.0.0.1:5173` 的网页请求。每次打开都使用当前登录身份向本机后端查询项目归属和配置目录，只接受项目 ID，不接受网页直接指定路径或命令；拒绝网络共享和设备路径。浏览器若询问访问本机网络，需要允许该本地页面。

该服务在宿主机运行，独立于 Docker；当前本机已启动，重启 Windows 后需再次执行脚本。日志位于 `tmp/workspace-opener*.log`，不记录令牌、请求正文或目录内容。自定义本机后端端口 / 网页端口时可直接运行 `scripts/workspace_opener.py --backend <本机 API 前缀> --origin <本机网页来源>`。

## 数据与运行语义

- `workspace_id` 只负责分组。现有 `Conversation.id` 同时作为 `session_id`，继续用于消息、LangGraph checkpoint 和 Langfuse session，不重新生成。
- 同一工作区的多个会话使用各自的消息历史和执行记录。工作区不自动共享聊天上下文；已有用户级记忆和知识库权限保持原来的范围。
- 移动会话不会中断模型任务；切换会话只断开当前界面的事件读取，后台继续运行。切回或刷新时通过原有 SSE 日志恢复。
- 移除工作区会把会话移到“最近”，保留历史、任务和 Session ID。删除会话是另一项需要确认的操作，运行中的会话必须先停止任务。
- 未加入项目的会话默认显示在“最近”，可通过会话菜单迁入工作区。启动迁移不修改它们的 ID 或消息。
- 所有工作区和会话 API 都限制为当前登录用户；移动时同时校验目标工作区和源会话。

## API

所有路径前缀为 `/api/v1/chat`，需要 Bearer token。

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET / POST | `/workspaces` | 列出 / 创建工作区 |
| PATCH / DELETE | `/workspaces/{id}` | 重命名 / 移除工作区，移除时保留会话 |
| GET | `/workspaces/{id}` | 获取本人项目配置，供本机目录服务校验 |
| GET / POST | `/workspace-sections` | 列出 / 创建项目分区 |
| PATCH / DELETE | `/workspace-sections/{id}` | 重命名 / 移除分区，保留项目 |
| POST | `/workspaces/{id}/archive` | 批量归档项目中的聊天 |
| POST | `/conversations` | 保留兼容旧客户端的预创建接口，新界面不再调用 |
| GET | `/conversations?limit=50&offset=0` | 按更新时间分页列出会话，单页最多 200 条 |
| GET | `/conversations?archived=true` | 分页列出本人归档会话 |
| GET | `/conversations/{id}` | 获取当前用户的会话元数据 |
| PATCH | `/conversations/{id}` | 更新 `title` 或 `workspace_id`，传 null 解除分组 |
| POST | `/conversations/{id}/archive` | 归档单个会话 |
| POST | `/conversations/{id}/restore` | 恢复会话，保留 ID |

会话元数据同时返回 `id`、`session_id`（相同 UUID）和可空 `workspace_id`。原有 stream、history、resume、cancel、traces 等接口保持原路径。

会话元数据新增 `has_messages` 和 `archived_at`。首次 `POST /stream` 可传 `workspace_id`；后端校验工作区归属后原子持久化首轮消息。项目元数据新增 `is_pinned`、`local_path`、`section_id`。
